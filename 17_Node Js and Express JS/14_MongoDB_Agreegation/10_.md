// Whop has registered the most recently

[

    }
  },

This aggregation pipeline finds the **most recently registered users** and returns some of their fields. Let's walk through it step-by-step.

---

### 1️⃣ `$sort`

```javascript
{
  $sort: {
    registered: -1
  }
}
```

### What it does

* `$sort` orders all documents by the `registered` field.
* `-1` means **descending order**.

So the **newest registration dates come first**.

Example (before sorting):

| name    | registered |
| ------- | ---------- |
| Aurelia | 2015-02-11 |
| John    | 2018-06-20 |
| Sara    | 2016-03-10 |

After sorting (`-1`):

| name    | registered |
| ------- | ---------- |
| John    | 2018-06-20 |
| Sara    | 2016-03-10 |
| Aurelia | 2015-02-11 |

Now the **most recently registered user is at the top**.

---

### 2️⃣ `$limit`

```javascript
{
  $limit: 3
}
```

### What it does

Keeps only the **first 3 documents** from the sorted result.

So this pipeline returns **the 3 most recently registered users**.

If you only wanted **one user**, you would use:

```javascript
{ $limit: 1 }
```

---

### 3️⃣ `$project`

```javascript
{
  $project: {
    name: 1,
    registered: 1,
    favoriteFruit: 1
  }
}
```

### What it does

Selects only the fields you want in the output:

* `name`
* `registered`
* `favoriteFruit`

Other fields like `age`, `tags`, `company`, etc. are **removed from the result**.

`_id` will still appear unless you explicitly remove it:

```javascript
_id: 0
```

### 🧠 Pipeline Logic (mental model)

```
documents
   │
   ▼
$sort by registered (newest first)
   │
   ▼
$limit 3
   │
   ▼
$project selected fields
```

---

💡 **Small optimization tip**

In large collections in **MongoDB**, it's sometimes better to `$project` early to reduce data size before sorting if documents are large.
